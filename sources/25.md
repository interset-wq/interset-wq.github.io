# basic-git-command

[Git 官方文档](https://git-scm.com/doc) · [GitHub 文档](https://docs.github.com/zh) · [GitCode 文档](https://docs.gitcode.com/) · [Gitee 文档](https://gitee.com/all-about-git)

> [!WARNING]
> 创建 repo 时，一定要创建 `README.md`、`.gitignore` 和 `LICENSE` 文件，减少不必要的麻烦。

## 常用命令

- **`git init`** —— 初始化一个全新的 Git 存储库并开始跟踪现有目录。它在现有目录中添加一个隐藏的子文件夹，该子文件夹包含版本控制所需的内部数据结构。
- **`git clone HTTPS/SSH`** —— 通过 HTTPS 或 SSH 创建远程已存在的项目的本地副本。克隆包括项目的所有文件、历史记录和分支。
- **`git add .或文件名`** —— 暂存更改。Git 跟踪对代码库的更改，但需要先暂存更改才能将其包含进项目历史。暂存是「暂存 → 提交」两步过程的第一步：通过分离暂存与提交，开发者可以完全控制自己的项目历史，而无需改变编码习惯。
- **`git commit -m "备注信息"`** —— 将快照保存到项目历史中并完成更改跟踪。提交就像拍照：所有 `git add` 暂存的内容都会成为这次快照的一部分。
- **`git status`** —— 将更改的状态显示为未跟踪、已修改或已暂存。
- **`git branch`** —— 显示正在本地处理的分支。
- **`git merge`** —— 将开发线合并在一起，通常用于合并两个分支上的更改，例如把功能分支合并回主分支以进行部署。
- **`git pull`** —— 用远程的更新更新本地开发线。队友向远程分支提交后，可用此命令将更改同步到本地。
- **`git push`** —— 用本地的提交更新远程存储库。

<details>
<summary>场景一：创建本地 repo，并发布到 GitHub（点击展开）</summary>

``` bash
# 初始化本地repo
git init my-repo

# 切换到本地repo目录
cd my-repo

# 创建本项目第一个文件README.md
touch README.md

# 暂存更改
git add README.md

# 提交修改
git commit -m "add README to initial commit"

# 关联远程repo
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY-NAME.git

# 推送到 github
git push --set-upstream origin main
```

</details>

<details>
<summary>场景二：对远程 repo 修改（点击展开）</summary>

``` bash
# 切换到已和远程repo关联的本地repo目录
cd repo

# 拉取远程repo,更新本地repo
git pull

# 切换到现有分支 `feature-a`
git checkout feature-a

# 做出修改

# 暂存被修改的文件
git add file1.md

# 提交修改
git commit -m "edit file1"

# 推送到 github
git push
```

</details>
